# 遠距離 LOD 2層共同仕様

2026-10-31 策定（Issue #14 / P2-spec）。フェーズ2の P2 実装（Issue #20）の入力として、遠距離 LOD のジオメトリ層とマテリアル層の共同仕様を固定する文書。判断前提 D1〜D6（docs/quality-roadmap.md）と性能上限（docs/verification-criteria.md「フェーズ 2 性能上限」）を前提とし、それらと矛盾する数値は置かない。

数値の出所は各所に明記する。現行 index.html（main head `a9fdba53cd63cfcb4e33dc0699c694a02be72af7`、blob `fcb41eb5319dd8fb6659276d636c9939f7ce4cd3`）の実装読み取りに基づくものを「現行値」、Issue #20 の本文に基づくものを「#20 の前提」、本仕様で新たに定めるものを「提案値（根拠: …）」と区別する。

## 0. 現行実装の事実（読み取り根拠）

仕様の数値は、まず現行ビルドの次の事実に基づく。

### 0.1 既存の LOD は至近の1段のみ

- 切替判定は `updateCloseLODs()` が毎フレーム行う。入条件: カメラ距離 d < 3.0 m、または画面高占有率 occ > 0.25。出条件: d > 3.3 m かつ occ < 0.225（±10% のヒステリシスで点滅を防ぐ）。occ = (0.58 / d) / (2·tan(fov/2))、fov = 55°、0.58 は個体高 0.36 m × 表示倍率（DISPLAY_SCALE = 1.6）。
- `setCloseLOD(p, on)` は、モーフ別に共有された Lo/Hi マテリアル間の差し替えと、至近専用部位（closeHead・closeBody・tailFan）の表示切替を行う。距離は `camera.position.distanceTo(p.pos)`（カメラ〜個体、シーン単位 = m）。
- テクスチャ解像度: Lo は 256×256（body／wing／tail、featherTexture）。Hi は 2048×2048 キャンバス（1024 単位で描画し ×2 スケール、featherTextureHi）で、初回の至近 LOD 入場時に遅延生成される（B6）。首テクスチャは個体別 512×256（neckCanvas）。

### 0.2 識別子の現行値（マテリアル層の誇張の起点）

- 翼帯（drawWingPattern、単位空間）: 2本の帯は u = 0.4375（幅 0.0898）と u = 0.5859（幅 0.0781）。Lo 256px では幅約 23.0 / 20.0 テクセル。帯色 alpha は 0.94（bar／checker）。翼の UV は wingGeo の正規化（u = x / 0.42、v = y / 0.21 + 0.5）で、u は根元 0 → 先端 1。
- 斑（checker）: 6×5 グリッドのセルに楕円（rx ≈ 0.44 × セル幅 = 256px で約 18.8 テクセル）、色 #16171c、alpha 0.5。tpattern は全面ウォッシュ alpha 0.28 ＋ 斑 alpha 0.85。
- 尾帯（tailTex、Lo）: 亜端帯は v = 26〜78 / 256（幅 52 テクセル、約 20.3%）、alpha 0.92。外側の白縁 14px ×2（P4）、先端の淡色 12px。
- 腰（rump）: モーフ別色を持ち、帯系モーフはほぼ白（blue-bar 0xf4f4f0、blue-checker 0xf0f0eb、t-pattern 0xedede8、red 0xf3efe4、silver 0xf2f2ed、brown-bar 0xf1ecdd。P4 で引き上げ済み）。spread-black は rump: null で体色、pied 0xe4e2da、white 0xe9e7e0。
- 翼下面（underwingTex、P4）: 地 #d9d9d3 に羽枝の淡いストローク、暗色は初列先端のみ（u = 0.78 → 1.0 のグラデーション、最大 alpha 0.85）。飛行中で翼が開いているときだけ下面パネル（underL／underR）を表示する。
- 頭部の色: head マテリアルは体色 × 0.78（multiplyScalar）。首は虹色テクスチャ（個体別、offset を毎フレーム書き換え）＋ fresnel シェル。

### 0.3 部位構成（ジオメトリ層の統合対象の起点）

`makePigeonMesh()` の読み取りによる、1羽あたりの構成。Lo 表示時のメッシュは約 30（帯ジオメトリを持つモーフでは約 38）で、至近専用部位（常時非表示）が別に約 57 メッシュある。

- 体幹・首まわり（7）: body（Sphere 径 0.16、20×15 セグメント、scale 1 / 0.86 / 1.38）、breast（bodyGeo 共用）、rump（Sphere 径 0.105、12×9）、neck（Sphere 径 0.105、18×14）、neckSheen（シェル）、breastPatch（Sphere 径 0.112、16×12）、breastSheen（シェル）
- 頭部（10）: head（Sphere 径 0.056、14×11、headG 配下）、beak、cere、twig（営巣期の小枝、通常は非表示）、eye ring / eye / pupil ×左右。このうち head を除く 8 点が basicHeadParts として至近で非表示になる微小部品
- 翼まわり（6）: wingL / wingR（wingGeo = ShapeGeometry、曲線分割 6、外形は x 0→0.42 の輪郭）、underL / underR（wingGeo 共用、翼面の 3mm 下）、foldL / foldR（wingGeo 共用、畳み翼パネル）。翼は root ピボット wingLP / wingRP（位置 ±0.05, 0.045, 0.015）の回転で駆動され、振幅 wingA = sin(flapPhase) × 1.02 − 0.08（滑空時 0.32、畳み係数で減衰）
- 尾（1）: tail（PlaneGeometry 0.175 × 0.2）
- 帯ジオメトリ（barsGeo モーフのみ 8）: wingL / wingR / foldL / foldR の各面に帯 Box 2 本（0.036 / 0.031 × 0.0035 × 0.175）
- 脚（6）: leg / foot / ankle ×左右。毎フレーム位置を書き換える歩行・着地アニメーションの対象
- 至近専用（Lo で非表示）: closeHead 11、closeBody の趾 32、tailFan 14（羽 12 ＋ 白縁ストリップ 2）
- その他: exclaim スプライト（イベント表示、LOD と無関係）

### 0.4 大気（fog）の現行値

- scene.fog は晴天時 near 700 / far 2600。天候で寄せられ、雨では near 90 / far 620、雪では near 110 / far 700 まで下がる（updateDaylight の読み取り）。
- したがって晴天時の対象距離帯（15〜30 m）では fog による減衰はほぼ 0 で、遠距離で識別子が弱る主因は fog ではなく、画面上の画素数不足とテクスチャ縮小（ミップ平均化）によるコントラスト低下である。

## 1. 目的と適用範囲

- 目的: 遠距離の鳩を「細部を捨てて識別子を誇張した姿」に切り替え、遠景でも群れがカワラバトの識別子を持つ集団として読める状態と、鳩のドローコール削減を両立させる（ロードマップの伸ばしどころ 3、Issue #20 の前提）。
- 適用範囲: 鳩個体（24 羽）の描画のみ。街・建物（単一メッシュ化済み）は対象外。至近 LOD の仕様は現行のまま変更しない。歩行の読み向上を目的とする変更は含まない（D1）。

## 2. 全体構成: 3段切替

既存の至近 LOD の枠組みを 3 段へ拡張する（#20 の前提）。

| 段 | 条件（カメラ〜個体距離） | 姿 |
|---|---|---|
| 至近（Hi） | 現行どおり（入 d < 3.0 m または occ > 0.25、出 d > 3.3 m かつ occ < 0.225） | 現行の至近 LOD |
| 標準（Lo） | 上記以外で、遠距離の出条件より手前 | 現行の Lo |
| 遠距離（Far） | 入 d ≥ 15.0 m、出 d ≤ 13.5 m | 本仕様の2層を適用した姿 |

- 遠距離の入距離 15.0 m は #20 の前提（目安 15 m 以遠）を固定値として採用する。出距離 13.5 m は提案値（根拠: 至近 LOD が ±10% のヒステリシスを使う現行の考え方をそのまま適用し、15.0 × 0.9 = 13.5 とする）。
- 遠距離の判定には occ を使わない（提案。根拠: occ は至近で「画面を大きく占める個体」を救うための補助条件であり、遠距離帯は距離だけで単調に決まる。fov 55° では 15 m の occ は約 3.7% で、視点による体感差より距離の統一を優先する）。
- 至近と遠距離は距離帯が重ならないため排他であることを仕様として明記する（状態は close / standard / far のいずれか 1 つ）。

## 3. ジオメトリ層仕様

### 3.1 統合対象

- 体幹クラスタ: body ＋ breast ＋ rump を 1 メッシュへ統合する。rump の白は体色と混ぜず、頂点カラー区画として分離したまま保持する（統合条件 1）。
- 頭首クラスタ: head ＋ neck ＋ breastPatch を 1 メッシュへ統合し、濃色マスとして体幹から分離する（#20 の前提）。neckSheen / breastSheen の fresnel シェルは遠距離では表示しない（遠距離では角度依存の光沢が判別できず、シェルの 2 メッシュは削減対象とする）。
- 翼: wingLP / wingRP のピボット構造と wingGeo の外形は変更しない（統合条件 4）。下面パネル underL / underR はピボット配下のまま連動させる。
- 尾: 現行 tail（1 枚）のまま統合しない。tailFan は至近専用のままとし、遠距離では使わない。
- 脚: leg / foot / ankle は毎フレームのアニメーション対象のため統合しない。遠距離でも表示を維持する（赤い脚は処分済み基準の項目 7 の判別要素であり、地上姿勢の識別子として残す）。

### 3.2 遠距離で非表示にする微小部品

- basicHeadParts のうち beak・cere・eye ring・eye・pupil（8 メッシュ）を遠距離では非表示にする（#20 の前提「遠 LOD では微小部品を非表示にする」）。
- 帯ジオメトリ（barsGeo モーフの 8 メッシュ）は遠距離では非表示にし、帯の判別はマテリアル層の誇張したテクスチャ帯へ寄せる（二重の帯表現を避け、ドローコールを削減する）。
- twig は現行どおり状態依存の表示とし、LOD では扱わない。exclaim スプライトも LOD の対象外とする。
- 至近専用部位（closeHead・closeBody・tailFan）は現行の visible 制御のまま、遠距離では常時非表示である（新規の処理は不要）。

### 3.3 低ポリ化の目安

- 統合後の体幹クラスタの三角形数は、現行 body 単体（Sphere 20×15、約 300 三角形）と同等以下を目安とする（提案値。根拠: 統合で部位間の重なりが消えるため、輪郭の解像度を body 単体並みに保っても、総三角形数は現行 3 部位の単純合計を下回る）。
- 頭首クラスタも同様に、現行 head 単体（14×11）と neck（18×14）の中間程度を目安とする（提案値。根拠は体幹と同じ）。
- 三角形数の実数は本仕様では固定しない。P2 実装でジオメトリの実測値を記録する（受入条件案 6）。

### 3.4 削減量の見込み（内訳）

1 羽あたりの表示メッシュ削減は、頭部微小部品 8、帯ジオメトリ 8（対象モーフのみ）、体幹統合 3 → 1 で 2、頭首統合 3 → 1 で 2、シェル除去 2、の合計約 22（帯ジオメトリのないモーフでは約 14）を目安とする（提案値。根拠: 0.3 の部位構成の読み取り）。実測は P2 実装の計測で行う。

## 4. マテリアル層仕様

誇張の倍率は #20 の前提（帯・斑・尾帯のコントラストと太さを 1.5〜2 倍）の範囲内とし、本仕様では下限を固定する。上限側（2 倍まで）の調整は P2 実装が指定視点の確認で行う。

### 4.1 翼帯・斑

- 帯幅: 遠距離バリアントでは現行の 1.5 倍を下限とする。狭い方の帯で 0.0781 × 1.5 ≈ 0.117（256px で約 30 テクセル）、太い方で 0.0898 × 1.5 ≈ 0.135（約 34 テクセル）。
- 帯のコントラスト: 帯色の alpha は現行 0.94 から 1.0 を上限に上げる。地の色は体色との関係を保つため変更しない（誇張は帯側のみで行う）。
- 斑（checker / tpattern / red）: セルの配置と大きさは現行のまま変えず、alpha を現行の 1.5 倍を下限に上げる（checker 0.5 → 0.75、red 0.38 → 0.57。tpattern の斑は現行 0.85 で上限に近いため 1.0 を上限とする）。セルを大きくしないのは、標準段の模様との同一性を保つためである。

### 4.2 尾帯

- 亜端帯の v 幅は現行 52 / 256 の 1.5 倍（78 / 256、約 30%）を下限とする。帯の v 位置（先端側の淡色縁との関係）は統合条件 1 の区画保持に従い変えない。
- 外側の白縁（P4）は現行のまま保持する。

### 4.3 腰の白と翼下面

- 腰: 帯系モーフの rump 色は現行値（ほぼ白、0.2 の読み取り値）を維持し、ジオメトリ統合後も頂点カラー区画として保持する（統合条件 1）。spread-black の rump: null（体色）は P1 の決定どおり維持する。
- 翼下面: 現行 underwingTex をそのまま使い、白の面積を減らさない（暗色グラデーションの開始位置 u = 0.78 を遠距離側へ広げない）。遠距離でも飛行フラッシュ（P4）の見え方を同一に保つ。

### 4.4 頭＋首の濃色マス

- 遠距離の頭首クラスタは、虹色テクスチャ（個体別 512×256、offset 回転）を使わず、単色の濃色とする。明度は体色 × 0.62 を上限とする（提案値。根拠: 現行 head は体色 × 0.78 で、遠距離では首の虹色が平均化して体幹に埋もれる。体幹との分離には明度差の拡大が必要で、0.78 のさらに 0.8 倍を採る）。
- 首の虹色そのものは至近・標準段の基準（処分済み項目 6）であり、遠距離の単色化で変更しない。

### 4.5 大気遠近法への対抗

- 0.4 のとおり、晴天時の対象距離帯では fog の減衰はほぼ 0 であり、識別子の劣化の主因は画素数不足とテクスチャ縮小による平均化である。対抗は fog の変更ではなく、4.1〜4.4 のコントラスト・太さの下限固定と、統合条件 2 のテクセル予算（縮小専用テクスチャを作らないこと）で行う。
- 天候時（雨・雪で fog が near 90〜110 / far 620〜700 まで寄る条件）の遠距離の見えは、本仕様の固定対象にしない（未確認事項）。

## 5. 統合条件（4点の固定）

2層は次の 4 条件を同時に満たす場合にのみ成立する。P2 実装はこの 4 条件を崩してはならない。

### 条件 1: 誇張ゾーンの UV / 頂点カラー区画の保持

- 翼の UV（u = x / 0.42、v = y / 0.21 + 0.5 の正規化、u は根元 0 → 先端 1）を変更しない。マテリアル層の帯・斑の誇張は、この UV 区画の内側でのみ行う。
- 尾の UV（亜端帯の v 区画 = 26〜78 / 256 を基準とする配置）を変更しない。
- 体幹統合後も rump の白区画を体色区画と分離して保持する（頂点カラーまたは専用 UV 区画）。統合を理由に白区画を体色へ平均化しない。

### 条件 2: 帯が読める最小テクセル予算

- 帯を持つテクスチャ（翼・尾）の解像度は現行 Lo と同じ 256px を下限とし、遠距離専用に解像度を下げたテクスチャを作らない。
- 遠距離バリアントでの帯幅は、翼の狭い方の帯で約 30 テクセル以上（0.117 × 256）、尾帯で約 78 テクセル以上（78 / 256 の v 幅）を下限とする（4.1 / 4.2 の 1.5 倍の下限と同一値）。
- 根拠: 現行 Lo 256px では帯は 20〜23 テクセルで描かれている。128px へ半減すると誇張前の帯が 10 テクセル級になり、1.5 倍の誇張でも判別の余地が狭まる。解像度を維持し、幅の誇張で判別を確保する。

### 条件 3: 切替距離帯の統一

- ジオメトリ層とマテリアル層は、同一の状態変数（far 段）で同じフレームに切り替える。層ごとに別の距離判定を持たない（二重のポップインを防ぐ。#20 の受入条件「二重のポップインがないこと」に対応）。
- 距離帯は 2 章の固定値（入 15.0 m / 出 13.5 m）を使い、至近 LOD の判定（updateCloseLODs）と同じ毎フレーム判定の枠組みに載せる。
- 切替は表示物（メッシュ・マテリアル）の差し替えのみで、個体の位置・姿勢・状態には触れない。

### 条件 4: 飛行時の羽ばたきシルエット保持

- 翼の root ピボット（wingLP / wingRP）と、その回転駆動（wingA の式、畳み係数、滑空値）は現行のまま変更しない。遠距離ジオメトリはピボット配下の翼外形（Shape アウトライン）を保持し、低ポリ化でも輪郭のポリラインを変えない。
- 下面パネル（underL / underR）は現行どおり翼ピボットの配下で連動し、表示条件（飛行中かつ翼が開いているとき）も変更しない。
- 尾は飛行時の扇開き（tailFan）を遠距離では使わない現行運用を維持する。遠距離の飛行シルエットは翼と尾板（tail）で構成する。

## 6. 性能上限との関係

- 本仕様は docs/verification-criteria.md のフェーズ 2 性能上限（視点別: 最悪ケース avgCalls ≤ 88、路面 ≤ 455 等。構造上限: totalNodes ≤ 4046、programs ≤ 45、geometries ≤ 683、textures ≤ 88、usedJSHeapSizeMB ≤ 102）を前提とし、上限を押し上げる要素を持たない（遠距離 LOD は削減方向の変更である）。
- 遠距離バリアントの追加テクスチャは 8 枚を上限とする（提案値。根拠: 誇張が必要なのは翼パターン 7 種（bar / checker / tpattern / spread / red / pied / white）と尾 1 種）。追加後も全体で構造上限 textures ≤ 88 の内側に収めること。
- 遠距離バリアントのマテリアル追加は morphMatsFor のキャッシュ構造（モーフ別共有）の内側で行い、個体別マテリアルを増やさない（B3 の構造を維持する）。首の個体別テクスチャは遠距離では使わない（4.4）ため、遠距離で個体別の新規生成は発生しない。

## 7. P2 実装（Issue #20）への入力: 受入条件案

Issue #20 の本文の受入条件（遠景 20 m 〜で群れが種の識別子を持つ集団として読めること、ドローコールの削減が計測で示されること、二重のポップインがないこと）に、本仕様から次の具体化を加える。

1. 指定視点・距離: docs/verification-criteria.md の P2 行（路面／俯瞰、15 m 以上）に従い、20 m 付近を含む距離で確認する。確認対象の識別子は、翼帯・斑・尾帯・腰の白・翼下面の白・頭首の濃色マスの 6 点とする。
2. 切替の単調性: 距離を 13.5〜15.0 m の帯で往復させても、点滅と二重切替（層のずれ）がないことを確認する（統合条件 3）。
3. 区画保持: 統合後の体幹で rump の白区画が分離して見えること、翼 UV が現行と同一であることを、描画とコード読み取りで確認する（統合条件 1）。
4. テクセル予算: 遠距離バリアントの翼帯・尾帯が統合条件 2 の下限を満たすことを、キャンバスサイズと描画パラメータの実測で示す。
5. 性能: 最悪ケース（全羽飛行）を含む計測を性能計測パネルで行い、verification-criteria.md の上限の内側であること。あわせて遠距離条件での avgCalls が現行ビルド比で減っていることを、同一手順の計測で示す（#20 の「ドローコールの削減が計測で示される」に対応。削減幅の数値は #20 自身が固定していないため、本仕様でも固定しない）。
6. ジオメトリ実測: 統合クラスタの三角形数と、1 羽あたりの表示メッシュ数の実測を記録する（3.3 / 3.4 の目安との差異があれば記録する）。
7. 退行なし: 処分済み 9 項目の基準状態（docs/verification-criteria.md）を下回らないこと。特に項目 6（首の虹色、至近）と項目 7（赤い脚、路面）は、遠距離変更の対象外の距離帯で従来どおり判別できること。

## 8. 未確認事項

- 天候時（雨・雪で fog が寄る条件）での遠距離識別子の見えは未確認。本仕様の固定は晴天条件を基本とし、天候時の扱いは P2 実装の検証記録に留める。
- 俯瞰視点でカメラ〜個体距離が実際にどの範囲に分布するか（15 m 帯にどの程度入るか）は未確認。P2 実装時に視点別の実距離を記録すること。
- 統合ジオメトリの三角形数の実数と、表示メッシュ削減の実績値は未確認（3.3 / 3.4 は目安）。P2 実装で計測して記録する。
- 頭首の濃色マス（体色 × 0.62 上限）の実ブラウザでの見えは未確認。P2 実装の指定視点確認で初めて判定される。
- 本仕様の数値のうち提案値と明記したもの（出距離 13.5 m、低ポリ化の目安、削減量の目安、濃色マスの 0.62、追加テクスチャ上限 8 枚）は、P2 実装の計測・確認で覆る事情が判明した場合、Issue #20 に記録したうえで見直してよい。その場合も統合条件 4 点の枠組みは維持する。
