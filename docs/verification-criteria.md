# 検証基準セット

2026-10-31 制定（Issue #6 / B2）。品質向上プログラム（docs/quality-roadmap.md）の各項目を検証するときの、視点・距離・判定基準を固定した文書。以後の検証はすべて本書の基準で実施し、結果は対象 Issue と docs/improvement-log.md に記録する。

## 検証の経路と前提

- 検証は、ビルダーの監査ハーネスとは別の、公開リンクを実ブラウザで開く独立経路で行う。監査ハーネスにはソフトウェア WebGL で 15 秒の読み込み上限があり、本作品のデスクトップシーンは初回描画がその予算に収まらないことが実測で分かっている。監査キャプチャの失敗をもって「未確認」の終端としない。
- 実ブラウザ経路には、ページ内 JavaScript の実行手段とコンソール読み取り手段がない。したがって数値の基準は、画面の DOM テキストとして読み取れるものだけを使う（性能計測パネルと HUD の表示テキスト）。DOM に現れない数値は推測で補わない。
- 検証のたびに条件を記録する: 視点、速度設定、フォーカスの有無、餌まき回数、対象個体とカメラ距離、計測の実行時刻（ハーネス計測の時刻を正とする）。

## 処分の語彙

| 処分 | 意味 |
|---|---|
| 確認 | 判定基準に列挙した要素がすべて目視で判別できた |
| 部分確認 | 対象の存在は見えたが、基準の細部まで判別できなかった |
| 未確認 | 条件を変えて複数回試みても判別できなかった |

## 視点の定義

| 視点 | 到達方法 | 主な用途 |
|---|---|---|
| 俯瞰 | 初期の観察カメラ（視点ボタンを押さない初期状態） | 街全体・群れ全体・飛行 |
| 路面 | 「路面で見る」ボタン | 街路の小物・看板・歩行中の鳩（距離 約 9〜15 m が実績範囲） |
| 川面 | 「川面を見る」ボタン | 川面の質感・流れ・反射 |
| 高架 | 「高架の遮音壁」ボタン | 遮音壁・高架まわり |
| 至近 | 追跡モードで個体を選び「鳩に寄る」（約 2〜5 m、実績 1.9〜3.4 m） | 個体の質感・模様・目のまわり |

## 性能計測の手順と記録項目

性能の数値は性能計測パネル（B1、PR #34 で導入）で取得する。

1. 公開リンクをブラウザで開き、ページの描画が始まるのを待つ。
2. 計測したい視点へ既存ボタンで移動する（視点の定義表のとおり）。最悪ケース（全羽飛行）は、視点ボタンを押した後で「群れを飛ばす」を押し、群れ表示が「飛行 24 羽」になってから計測する。
3. 画面隅の「計測」トグルを押してパネルを開く。
4. 「現在の視点で計測」ボタンを押し、表示が「計測完了」に変わるまで待つ（bench は 5 秒間）。
5. パネル内の数値テキストを画面読み取りで取得する。視点を変えて 2〜5 を繰り返す。

記録項目（すべてラベル付き DOM テキスト）:

- bench: avgFps / avgCalls / maxCalls / avgTriangles / avgFrameMs / maxFrameMs / frames
- snapshot: memory.geometries / memory.textures / usedJSHeapSizeMB / programs / totalNodes / shadow.updates / shadow.autoUpdate / shadow.framesRendered / boot.scriptStart / boot.decoded / boot.cityBuilt / boot.texturesReady / boot.firstFrame / boot.interactive
- あわせて視点名（全羽飛行時は併記される）と、その時点の群れ内訳（地上／止まり／飛行）を記録する。

フェーズ 2 の性能上限は、B1 の本計測（5 視点＋最悪ケース、Issue #5 の計測記録コメント 6542769651）に基づき、次節「フェーズ 2 性能上限」で数値固定済みである（2026-10-31 追記）。

## フェーズ 2 性能上限（2026-10-31 固定・相対ゲート）

B1 本計測（Issue #5 の計測記録コメント 6542769651、2026-10-31 20:10–20:26 JST、公開リンクの計測パネル入りビルド＝main の index.html blob e4ef6c46a9ff6aa3862cd933788110935f718266 を実ブラウザ経路で計測）の基準値に基づき、フェーズ 2 の性能上限を次のとおり固定する。

### 計測環境の留保（上限の性格）

- 基準値の計測環境はソフトウェアレンダリング相当の描画条件であり、avgFps は全条件で 2.0–2.35 にとどまった。以下の上限は実機性能の主張に使う絶対値ではなく、この基準値に対する悪化を検出する相対ゲートである。
- 判定は、基準値と同一の計測手順（性能計測パネル、本書「性能計測の手順と記録項目」）で得た値に対して行う。計測環境が大きく変わった場合は上限をそのまま適用せず、基準値の再計測を先に行う。

規則: avgCalls・avgTriangles・avgFrameMs の上限は基準値×1.2（端数は切り上げ）、avgFps の下限は基準値×0.8。括弧内は基準値。

### 使い方

- フェーズ 2 の各項目で受入条件に性能計測を含める場合、最悪ケースを含む計測で上記の上限・下限の内側であることを条件とする。本書「今後の品質項目の基準の定め方」第 4 点および P3 の「上限線」は本節を指す。

## 今後の品質項目の基準の定め方

フェーズ 2・3 の各項目は、Issue の受入条件に次の 4 点を明記してから着手する。本書の 9 項目表が書式の雛形である。

1. 指定視点: 本書の視点の定義から選ぶ（複数可）。
2. 距離条件: 判別を行うカメラ距離の範囲（例: 路面 約 10 m、至近 2〜5 m）。
3. 「確認」の基準: 判別できるべき要素を列挙する（存在ではなく要素単位で書く）。「部分確認」は存在は見えるが要素の細部が判別できない状態、「未確認」は条件を変えて複数回試みても判別できない状態を指す（語彙表のとおり）。
4. 性能への影響がある項目は、最悪ケース（全羽飛行時）を含む計測を性能計測パネルで行い、上限線以内であることを条件に含める。

### 1. 読む経路の固定

- 計測は必ず計測パネルの「現在の視点で計測」ボタンで行う。パネルに表示される snapshot 値は、クリック時点の値ではなく 5 秒の bench が終わった直後の値である。
- コンソール経由の `__QA__.snapshot().render` は、パネル値との比較に使わない。使う場合はラベルを `snapshot.render.*（コンソール）` と明記し、bench 平均とは別欄に記録する。

### 2. ラベルの完全一致

- 記録に使うラベルは、パネル表示ラベルと完全一致させる。bench は `avgFps`／`avgCalls`／`maxCalls`／`avgTriangles`／`avgFrameMs`／`maxFrameMs`／`frames`、snapshot は `memory.geometries`／`memory.textures`／`memory.usedJSHeapSizeMB`／`programs`／`totalNodes`／`shadow.framesRendered`／`boot.firstFrame`／`boot.interactive` とする。
- 裸の「calls」「triangles」「drawCalls」「fps」は記録ラベルとして禁止する。どの量か判別できないためである。

### 3. 描画収束の前条件

- ボタン押下の前条件は次のすべてを満たすこと。ローダーが消え、HUD の群れ内訳が表示され、目的視点への移動が完了していること。
- 目的視点へ移動後、カメラを動かさずに 5 秒以上待機すること。この 5 秒は bench とは別の待機である。
- bench の 5 秒間もカメラを動かさないこと。bench 中のカメラ移動は、視錐・LOD の掃引履歴を bench 平均に混ぜる。
- 待機・bench 中のカメラ移動・視点ボタン押下・餌まき・飛行・フォーカス変更があった場合は、その計測を無効とし、理由とともに記録する。

### 4. カメラ・LOD レジームの固定

- カメラモード（orbit／follow／pov／play）、視点ボタン名、フォーカス個体名と `focus.dist` を必ず併記する。`focus.dist` だけでは不十分であり、カメラモードと視点ボタン名も一致させる。
- boot 計測の経路は「新規セッション（新規タブ・キャッシュ状態を記録）→ 目的視点ボタンへ直行 → 上記 3. の待機 → 計測」とする。目的視点が俯瞰の場合は、広域ビュー（観察カメラ）への明示的な復帰を boot の基準点とする。いずれの経路でも、任意機能（夕方・夜間ボタン、雨・雪の誘発、餌まき、群れ飛行、画質 Ultra への切替、反射 on への切替、鳩への接近・フォーカス）に触れる前に記録する。
- boot 経路で、目的視点以外の視点ボタン・接近（3 m 未満または画面占有率 0.25 超による close 進入）・餌まき・飛行・画質／反射／天候の変更を経由した場合は、セッション履歴としてすべて記録し、boot 値として扱わない。
- 比較対象の 2 回は、同じ boot 経路・同じ視点ボタン・同じカメラモード・同じ時間速度で取得すること。

### 5. 時間速度と群れ内訳

### 6. 読む項目名の統一

- 判定の主軸は、パネル snapshot の `programs` と `totalNodes`、bench の `avgCalls`／`avgTriangles`／`avgFps` とする。
- snapshot の `memory.geometries`／`memory.textures` は、boot 比較では参考値とする。理由は、両値が「シーンに存在する数」ではなく「セッション開始からその時点までに一度でも描画された異なるジオメトリ／テクスチャの累積種類数」であり、セッション履歴に依存するためである。構造上限との照合は最悪ケースを含む計測でのゲートとして残し、上限値は引き上げない。参考値扱いは boot 回同士の傾向比較に限る。天井超過は boot 計測を含むいずれの計測で生じても退行として扱う。
- `snapshot().render.calls`／`triangles`／`fps`／`frameMs` は、単一フレーム値であるため判定値に使わない。参考として記録する場合は、連続 3 回の読み（1 秒間隔）をセットで記録し、単独値を判定に使わない。

### 7. セッション履歴チェックリスト

- programs 単独の数値比較は行わない。

### 8. 繰り返し回数

### 14. avgCalls の表示形式の記録粒度（第78回改訂）

- 小数表示と整数表示の違いを記録に明記する。avgCalls ≠ maxCalls の場合は小数表示、avgCalls = maxCalls の場合は整数表示になる。表示形式の違いはパネル表示の変更を示すものではなく、整数表示の丸め誤差は ±0.5 程度で、100 を超える回間差の結論を覆すものではない。
- maxCalls = avgCalls の正確な一致は「全フレームの calls が完全に等しかった」ことを意味する旨を注記する。
- 集計意味論（avgCalls・maxCalls の対象フレーム数と窓）そのものは未確定のため、条件 A の判定前提としては対照計測 (i)〜(iii) とパネル集計方法の src/ 読み戻しによる別途の確定を待つ。
- 「注目個体の違い」説は第76回と第77回で方向が反転したため、主因としては棄却されたものとして記録する。
